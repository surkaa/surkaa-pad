# 更改主密码与盐

## 使用与恢复

设置 → 数据管理 → 密钥派生配置 → 更改密码与盐。

- 输入当前主密码、新密码并重复确认。关闭“同时更改密码”时只更换盐，密码不变。
- 每次生成新的随机盐；默认保持已有内存成本，也可以选择新的内存成本。保留既有 Debug/Release 参数差异，不强制把开发数据改成正式参数。
- 首次创建与改密共用内存成本选项。Debug 默认硬编码为 1024 KiB（1 MiB）；Dev 安装包即使使用 Release 优化构建，也可按应用标识/产品名识别并选择 1 MiB。此修改不改变已有 Vault 或 Release 的派生默认值。正式版只提供 64/128/256 MiB 的新成本选项，改密仍默认保持当前成本；说明更高成本通常增加暴力破解的时间/内存开销，同时增加本机解锁耗时/内存占用，不能替代强主密码。1 MiB 明确标注仅供开发测试。原理参见 [Argon2 RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html#section-7.4)。
- 先统计当前权威存储的全部对象和大小，检查可识别性、附件引用及认证密文，并实测旧密码验证、新密钥派生和小样本加解密。统计不修改用户数据；统计后数据变化时必须重新统计。
- 估算的是本机派生与加解密耗时，不是完成时间。磁盘读写、网络和读回校验可能占用更多时间；云端同时展示累计传输量估算和临时空间需求。正常云路径主要数据约为重加密数据量的 4 倍（源、临时、正式各读一次，上传一次）；备份 CRC 缺失时额外完整读取备份，界面按 5 倍保守估算。此前全量检查路径为 7 倍。GCM/Manifest 重写可能有少量大小差异；不包括改密检查点、请求开销和中断恢复的额外校验，不能视为严格流量上限。
- 当前单文件步骤小于 10 MiB 不展示单文件进度；10 MiB 到不足 1 GiB 为 10 个刻度，1 GiB 及以上为 100 个刻度（与界面文件大小换算使用相同的二进制单位）。读取、重加密写入、读回校验、备份与替换分别计数。既有流统计不增加读取或内存缓存；流读完后仍等待写入确认/哈希比对，通过后才显示本步骤 100%。OSS 服务端复制没有中间字节进度，只显示开始与完成。整体进度仅按已保存检查点的对象统计。
- 改密进行时显示按字节估算的剩余时间和本地预计完成时刻，跨日带日期。使用本次运行的已完成数据字节，将当前大文件的实际路径折算为部分原数据字节：完整路径按八步骤，云快速路径按实际四轮/五轮传输加权（重加密读取与上传计两轮），已提交目标恢复按剩余核对加权。云内复制仅计等待，不凭开始/完成事件虚增已处理量；确认可省略备份读回或发现目标已提交时，同时重算基准，不能把跳过的步骤当作刚传完的数据提高测速。不使用文件数量推算时间，也不把折算量当作已保存检查点或网络流量。积累至少五秒、处理量达到本次剩余数据的 1%（至多要求 1 MiB）后才显示估算，避免仅凭小元数据对象预测大 Vault；续改重新测速，已完成数据与暂停时间不计入本次速度。各步骤耗时、文件大小分布及网络变化会使估算调整，因此仅供参考。校验和保存配置仍按原流程完成，不因为预计时间归零而提示改密成功。不新增云端请求或持久化写入。
- 开始前关闭其他设备上的应用，完成前不能重新打开。旧版应用不认识改密记录，因此云端标记不是对旧版应用的强制锁。
- 本机迁移期间禁用日记、附件、AI、云模式和数据目录切换。可请求“当前对象完成后暂停”，不能在替换开始后取消或回滚。
- 断网、退出或重启后在解锁页续改。**续改只接受新密码；只更换盐时仍输入原密码。** 不要卸载应用、清理应用数据或删除改密记录。第一版从发起设备本机记录恢复，不支持卸载后只凭云端记录重建整个任务。
- 完成后旧生物解锁凭据失效；仅此前启用生物解锁时提示需要重新启用。其他已配置云同步的设备先用本机旧密码解密本机 OSS 配置，再输入新密码更新本机凭据并丢弃旧缓存；不会再次重加密云端数据。解锁页底部感叹号按钮可查看此说明，检测到未完成改密时仍突出显示“继续改密”。

本地模式只修改本机数据，不修改已断开云同步的旧云端副本、导出文件或外部备份。旧副本仍然需要旧密码；不能把旧密钥副本直接混入新 Vault。

## 覆盖范围与第一版边界

权威数据来自云同步开启时的 OSS，或关闭云同步时的 LOS。处理日记主文件、已加密附件、AI 会话/消息块、云同步设置，以及本机已加密的密码校验、OSS、AI 配置。未加密附件原样保留。云模式下 LOS 是缓存，完成时清除旧缓存。

未知非空对象、孤立附件、缺失附件、未完成附件事务或已有附件 multipart 会话会阻止启动。零字节目录标记可以保留。

- CTR 大附件逐块重加密，不把整文件载入内存，也不落盘明文。沿用同一 IV，但必须验证新旧密钥不同。
- 当前 GCM 格式需整对象认证；第一版拒绝超过 64 MiB 的单个 GCM 对象，避免迁移中内存耗尽。恢复记录限制为 64 MiB，超限在修改数据前拒绝。
- 既有 CTR 没有认证标签。迁移的 SHA-256 校验保证转换前后内容一致，不能检测或修复已经发生的源数据篡改。
- 本地空间不足（包括项目现有安全余量）不允许开始。临时空间估算为最大对象大小加预留量后乘三，覆盖新密文、旧密文备份和替换临时文件。
- 支持未启用、已启用及已暂停版本控制的 OSS 桶，不再要求 `oss:GetBucketVersioning` 权限。只操作当前可见对象，不使用 `versionId` 永久删除任何历史；已有历史及删除标记遵循 OSS 自身规则，暂停状态的 null 版本不等同于逐次备份。空间估算不包含历史占用，启用版本控制后旧密文和临时对象历史可能继续占用空间。旧密码仍能读取改密前的历史数据；持有新密钥且能读取历次恢复记录历史的人可能逐级解出旧密钥，读取旧备份或已删除的历史内容。这是保留恢复材料的取舍，不会让只知道旧密码的人获得新密钥。操作期间不得更改桶版本控制、生命周期或删除策略。
- 不保证擦除 SSD/文件系统已删除内容，也不会让已经导出的明文、旧备份或先前复制的旧密钥失效。

## 数据提交顺序

后端 `vault_key_change` 是独立迁移模块，不把领域加密职责放入 LOS/OSS 通用读写接口。

1. 一次流式读取原密文，同时计算原密文及解密内容的 SHA-256、生成新密文并写到本次事务的临时位置，记录实际生成的新密文哈希。GCM 在既有大小上限内认证解密，CTR 保持有界缓冲、不落盘明文；必须完整读到 EOF 且写入成功后才能进入读回校验。
2. 一次读回临时密文，同时检查密文大小/哈希及解密内容哈希，分别与生成时的基准比较。不能用读回结果自己充当基准，也不能仅验证明文一致。
3. 持久保存“临时密文已验证”的检查点；云模式下本地和云端都必须成功。
4. 正常云流程先 HEAD 确认本事务备份不存在，再用源 ETag 条件复制旧密文备份，已存在时拒绝覆盖并交由续改完整核对。禁止覆盖头仍作为未启用版本控制时的额外保护，但版本控制桶会忽略它，安全性来自独占任务、独立事务路径及存在性检查。备份大小和 ETag 必须与复制结果一致；服务端 CRC64 与生成阶段在源密文流上算出的 CRC64 相同才通过。没有 CRC64 就完整读回备份核对源 SHA-256，有 CRC 却不匹配则立即停止。替换前只 HEAD 确认正式对象仍是原大小/ETag，再以已经验证过的临时 ETag 条件复制到正式位置；最后按复制返回的正式 ETag 完整 GET，大小和 SHA-256 必须与生成时的新密文一致。本地以及中断恢复仍完整核对目标、临时密文和备份。所有复制均不请求修改 OSS 服务端加密/存储类型；失败保留恢复材料，不退回下载重传。
5. 持久保存已完成索引和新 ETag，最后删除该对象的临时密文、旧密文备份。
6. 附件先处理，日记主文件最后处理，写入新的附件 ETag，但不修改日记编辑时间。
7. 所有对象完成后才切换云端 bootstrap，再清除旧缓存、切换本机 bootstrap 和活跃密钥。
8. 前端禁用旧生物凭据、逐项保存本机加密配置并读回确认；后端收到确认后清理剩余临时对象、云记录、本机记录及配置备份，解除操作锁。

正常云路径的源 GET 与临时读回 GET 都附带 `If-Match`，ETag 不符返回 412，绝不降级为无条件读取。临时对象仍完整解密，明文 SHA 与生成时的明文基准一致，密文 SHA 与实际上传的字节一致；正式对象仍完整核对密文 SHA。只有本次运行刚验证的临时对象可走快速路径，恢复时不能仅凭持久化的 ETag/CRC 省略全量核对。ETag 只是对象身份，CRC64 是传输差错检查，不提供 SHA-256 的抗碰撞保障；本次明确仅在正常云备份环节接受这项折中。

`x-oss-hash-crc64ecma` 使用 **CRC-64/XZ**，不能误用 CRC-64/ECMA-182；[OSS CopyObject 文档](https://help.aliyun.com/zh/oss/developer-reference/copyobject)说明复制结果不保证有 CRC。条件复制使用 OSS4 签名，复用已有 rustls 客户端和凭据；不将 OSS 原生条件头混入 rust-s3 的 AWS4 签名。条件只约束复制源，并不原子锁住目标，故仍要求其他设备退出和本机普通业务冻结。存在性、大小、ETag、CRC 合并到一次 HEAD，只有 404 表示不存在；权限错误、异常响应及必需元信息缺失停止。HTTP 200 也必须有有效 CopyObjectResult，不能把错误 XML 当成功。

目标已经是校验过的新密文时直接补检查点，不重复加密；目标既不匹配旧密文也不匹配新密文时停止，不覆盖未知数据。目标数据/ETag 替换中断时凭已验证的临时密文和旧备份修复。云端恢复或清理前验证事务身份，拒绝覆盖其他任务。

本机记录保存在 Rust 应用配置的 `pendingVaultKeyChange` 字段；云记录为 `vault/key-change.json`，临时对象为 `vault/key-change/{transaction_id}/{index}.enc` 和 `{index}.old.enc`。改密记录为 V2，新增已验证临时 ETag 和本机源 CRC；V1 先通过原认证上下文解密，再重新封装旧密钥、加密检查点升级为 V2，并在升级记录持久成功后继续。旧检查点缺少这些证据时仍按全量恢复路径运行。KDF/bootstrap 头是公开参数，其余检查点和本机配置使用新密钥认证加密。**只保存新密钥封装的旧密钥，绝不保存旧密码能取出新密钥的反向桥。** 主密码不持久化，派生密钥不传到前端。

最终检查点保留到本机配置全部保存成功。因此前端只保存了部分配置、确认响应丢失、清理失败时，重复续改和确认是安全的。配置备份里仍有未清理恢复记录时也保持操作锁。

### 云端改密占位

OSS 的 [禁止覆盖头](https://help.aliyun.com/zh/oss/developer-reference/putobject) 在启用和暂停版本控制的桶中无效，而且 [PutObject 不支持 If-Match/If-None-Match](https://help.aliyun.com/zh/oss/user-guide/0017-00000245)，不能直接套用 S3 条件写入实现云锁。

- 本机先持久保存 Journal，再发布独立的 `vault/key-change-claims/{transaction_id}.json`（仅版本、随机任务 ID 和 Vault ID，无密码或密钥）。完整枚举当前占位，只有自己是唯一任务时才允许建立活动 Journal。依赖 [OSS 的原子写入和强一致枚举](https://www.alibabacloud.com/help/en/oss/user-guide/what-is-oss/)，不适用于弱一致的其他对象存储。
- 多方同时申请可能都失败，但不能同时改密。失败方只撤回自己的占位；PUT/DELETE 响应丢失时保留本机恢复记录，核对后重试。不按随机 ID 大小选赢家、不设置自动过期，也不夺取暂停任务的占位。
- 活动 Journal 已确认属于本任务时，可继续原任务，不受尚未获准的竞争占位阻塞。没有 Journal 时必须重新确认唯一占位；只有没有进度、没有已验证临时密文、没有本事务临时对象的竞争者才可自动撤回。旧版暂停任务可在核对身份后补建占位再恢复。
- 最终确认先清理本任务当前临时对象，再删除当前活动 Journal，最后撤回本任务占位；只隐藏当前对象，绝不枚举或永久清理历史版本。普通操作与其他设备更新凭据都会检查活动 Journal 和占位。
- 这不是对旧版客户端或外部工具的强制写锁，仍须关闭其他设备，保护这些控制路径不被生命周期规则或外部工具改写。需要发起设备的本机恢复记录，不支持复制恢复配置到多台设备并行续改。

## 匿名性能报告

完成或暂停改密后，在 **设置 → 诊断信息 → 改密统计** 查看和复制最近一次报告。报告只保存在本机 `app-state.json` 的 `lastVaultKeyChangeReport`，不上传云端；清除恢复记录不会清除报告。JSON 查看复用通用的可折叠组件。

- 准备、派生与自检分别计时；实际数据处理记录步骤耗时、逻辑存储操作数/失败数、读取内容字节、供给写入端字节和云内复制字节。小于 10 MiB 的对象也参与统计，不受界面进度刻度限制。
- 同步 CTR/GCM 转换和 SHA-256/CRC64 单独计时，不包含上游网络等待。读取块的 `next().await` 时间单独累计，排除消费者处理间隔，但包含网络/磁盘及任务调度；不是纯网络时间或操作系统 CPU 使用率。
- 读取流生命周期、上传、复制及其内部操作会重叠，不能把 `operations.totalMs` 相加作为总耗时。操作计数不是 HTTP 请求数；字节计数不包含协议头、SDK 内部重试及云锁/bootstrap 等少量控制请求，也不声称是计费流量。失败上传只记录已供给写入端的字节，不声称已成功提交。
- 活跃耗时包括后端数据迁移及最终确认，不包括用户暂停、输入密码和前端保存配置的间隔；准备阶段另列。正常续改累计此前统计；强制退出仅保留最近检查点，报告通过 `incompleteHistory` 标出缺失。旧任务无统计地续改也标记为部分历史。
- 仅保留十个最慢处理尝试的匿名索引、加密类型、大小与耗时，同一对象的重试可能重复出现；不记录附件名、Key、日记内容、密码、盐、Vault 身份或密钥材料，随机事务 ID 仅用于区分任务。统计不改变检查点格式、加密字节或提交顺序；随现有本机检查点保存，不为每个事件新增 I/O，结束时额外保存一次摘要。报告保存失败不会影响改密安全状态。

## 验证

测试覆盖每个存储 I/O 前后的失败、响应丢失后重读持久检查点、本地实际重启、单独换盐、GCM/CTR、源对象变化、损坏临时密文/备份、目标缺失恢复、未知/缺失对象、排队普通操作及 HTTP 响应流锁、前端部分保存和重复确认。合并流测试核对实际读取次数，并覆盖不完整 EOF、读取中途断流/截断、相同明文但不同密文的替换，确保双重哈希仍与生成基准匹配。单文件进度覆盖 10 MiB/1 GiB 边界、有界缓冲模拟 1 GiB、30 MiB 实际本地流、测试桶 12 MiB 流，以及写成功但响应丢失/校验失败不显示 100%。

请求计数测试使用只接受一个请求的本地 HTTP 服务，验证改密读取只发一次 GET，元信息查询只发一次 HEAD；覆盖空文件、二进制/分块传输、HTTP 错误、读取截断、断开连接、404 与缺失大小/ETag。云内复制模拟则断言每次成功复制仅发 PUT + HEAD，不退回客户端下载重传。

快速路径测试核对每个对象的完整读取次数：源/正式合计两次、临时一次，备份只在 CRC 缺失时读一次。覆盖 CRC 不匹配、已有备份禁止覆盖、复制结果大小/ETag/CRC 冲突、源及临时对象变化、正式复制损坏、各阶段断流/截断、每个 I/O 前后失败与响应丢失、V1 密钥封装迁移和升级检查点保存失败。实桶条件测试确认错误 ETag 返回 412、已有备份返回 409且不改对象，支持带中文/空格/特殊符号的 Key，并校对服务端 CRC-64/XZ。

版本控制兼容测试模拟覆盖/删除后保留历史、服务端忽略禁止覆盖头、竞争失败及响应丢失。穷举两任务的 20 种交错和三任务直到完成释放的 34,650 种交错，并运行异步竞争；核对已开始任务不被抢占、损坏/外来占位不被覆盖或删除、未知备份不被覆盖。实桶流程覆盖活动 Journal 存在时忽略未获准竞争者、Journal 缺失时拒绝冲突、旧任务补建占位及结束清理不触碰竞争者。不为测试启用或暂停共享测试桶的版本控制。

真实 OSS 测试使用 `.env` 凭证、显式选定的测试桶与唯一 `rust-tests/` 前缀，覆盖超过 multipart 阈值的流式附件、暂停续改、bootstrap 最后切换、分片清理范围、云锁重建和其他设备仅更新本机配置。通过后清理前缀，失败保留现场。未对正式数据执行改密；实际真机强杀和物理断电仍需独立验证。

云内复制测试包含 1 GiB 两侧、6 GiB、复制失败及目标大小异常的 HTTP 请求模拟，断言没有源文件 GET 或客户端重新上传，并且只报告开始/完成。另有显式运行的大对象实桶测试：只从本机上传 8 MiB seed，通过云内分片拼接出 1 GiB + 8 MiB 的样本，验证云内备份和覆盖、大小及首/中/尾 Range 抽样内容，成功后删除全部样本并确认无残留分片。该测试默认忽略，避免普通 `cargo test` 反复创建 GiB 级样本；它不等同于 GiB 级文件的全量改密测试。

注意：`OssClient::from_env()` 不会自动改用测试桶，`.env` 也供管理工具使用，可能指向正式桶。运行云端测试前必须核对并显式指定测试桶，不要为了测试覆盖 `.env`。本项目 PowerShell 测试示例：

```powershell
$env:ALIYUN_BUCKET_NAME = 'surkaa-test'
cargo test
```

单独运行大对象复制验证（必须是 `surkaa-test`，代码也会校验桶名）：

```powershell
$env:ALIYUN_BUCKET_NAME = 'surkaa-test'
cargo test real_cloud_copy_above_one_gib_cleans_all_test_objects --lib -- --ignored --nocapture
```
