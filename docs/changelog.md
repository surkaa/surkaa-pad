# 应用更新记录

`src/data/changelog.json` 是应用更新描述的唯一数据源，应纳入 Git，与对应代码一起审查和提交。它不包含日记、用户设置或密钥，不需要加密和云同步；以后随安装包提供离线查看。

## 数据格式

顶层分组区分版本序列；每条记录只包含三个字段：

```json
{
  "updatedAt": 1793003388000,
  "version": "0.8.16",
  "description": "本版本的简短更新描述。"
}
```

- `updatedAt`：Unix 毫秒时间戳，展示时转换为设备本地时间。
- `version`：不带 `v` 前缀的版本号，不保留预览版记录。
- `description`：面向用户的一段纯文本，包含标点和英文在内，最多 100 个 Unicode 码点。不写 HTML，不在这里维护多份分类文本。

| 分组 | 对应内容 |
| --- | --- |
| `stable` | `src-tauri/tauri.conf.json` 中的非预发布版本，以及仓库最早的 `v0.0.1` 标签 |
| `windowsDev` | `src-tauri/tauri.dev.json` 的独立版本序列 |
| `androidDev` | `src-tauri/tauri.android-dev.json` 的独立版本序列 |

各组按版本号从新到旧排列。开发版 `0.4.x` 与正式版 `0.4.x` 不是同一次更新，不能混用已读标记或互相比较升级关系。

## 历史整理口径

最初整理时核对了仓库的配置变更、Git 标签、相邻版本之间的提交及必要的版本间净差异，历史基线保留 70 个版本条目：正式记录 64 条（含早期标签）、Windows 开发版 5 条、Android 开发版 1 条。历史预览版已按产品要求移除；后续版本按下述维护规则继续追加。

1. 优先使用**首次引入该配置版本号的提交作者时间**，而不是后续合并提交的时间。例如 `0.5.8` 使用 `995d2b3`，不是合入主分支的 `197c0f6`；Android Dev `0.4.10` 使用 `6bffafb`，不是后续合并提交。
2. 历史没有完整的安装包发布元数据，因此时间戳表示可追溯的版本变更时间，**不等同于安装包发布日期**。记录也不证明已发布安装包；例如整理时 `0.8.16` 仅已更新配置，尚未打包。
3. 版本描述概括该版本的主要用户可见变化；格式化、测试和内部拆分不逐条罗列，合并或重写历史中的重复功能不重复算作新增。例如 `0.8.9` 不再次宣称新增 `0.8.8` 已具备的 AI 上下文压缩。
4. 没有凭空补齐缺号版本，例如仓库里没有配置或标签证据的 `0.2.3` 不创建条目。没有新功能的版本如实描述配置、构建或修复事项。
5. **`v0.0.1` 是历史标签例外**：它指向 `6333073`，当时应用配置已经是 `0.1.0`。保留 `version: "0.0.1"` 以覆盖仓库标签，并在描述中标明差异；时间使用标签指向提交的作者时间。它与初始化配置 `0.1.0` 的日期不按版本大小递增。
6. 开发版长期沿用同一版本号；它的条目描述该版本号首次建立或更新时的变化，不代表之后每次开发构建都另有一条记录。共享功能主要查正式版记录。

以上记录可通过 `git log -p -G '"version"' -- src-tauri/tauri.conf.json src-tauri/tauri.dev.json src-tauri/tauri.android-dev.json`、`git show <提交>` 及 `git diff <前版本提交> <当前版本提交>` 复核。

## 后续维护

- 更新对应 Tauri 配置版本号时，同步在正确分组顶部新增一条记录，不修改 npm 包或 Rust crate 的内部工程版本号来代替应用版本。
- 新条目使用本次版本更新的毫秒时间戳；历史描述修订保留原来的版本时间，不改成修订当天，也不覆盖或删除旧版本。
- 概括新增、优化及修复；如果有兼容性或迁移风险，优先保留风险说明，即使需要省略次要美化事项。
- 运行 `pnpm test scripts/__test__/changelog.spec.js`：检查三个字段、100 字上限、排序、重复版本、当前配置覆盖，并在完整 Git 历史可用时核对历史版本及时间戳。历史追溯以本次整理基线 `8918b61` 为准，确保保留的 70 条不被遗漏或误改；预览版不再纳入审计，后续新版本可与 JSON 同次提交，不要求预知 Git 提交时间。
- Git 不可用或浅克隆时，仅跳过历史追溯检查，数据格式与当前配置一致性检查仍必须通过。
- 设置底部的“更新日志”入口与关于入口并列，导航到独立 `/changelog` 页面，不放入关于弹窗，也不提供版本类型切换。正式包只显示 `stable`；Windows 开发运行和 Dev 安装包只显示 `windowsDev`，Android 同理只显示 `androidDev`。开发运行使用 Vite 开发模式标记，Dev 安装包复用应用标识/产品名判断（Android Dev 沿用正式标识，因此需要产品名），不能仅按 Debug/Release 区分。识别失败时提示重试，不误展示其他平台记录。
- 描述按纯文本显示，日期使用设备本地时间，详细口径通过感叹号说明按钮查看。查看内容不访问云端。
- 升级提示及本机已读标记仍在 `TODO.md` 中，本次页面接入不实现它们，也不打包发布。
